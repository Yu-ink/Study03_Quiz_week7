# 문항 추가 (quiz-add)

카테고리 4개(한국사, 세계지리, 과학, 예술과 문화)에 새 문항을 **똑같이 n개씩** 만든다. 카테고리마다 문항 수가 같아야 하기 때문이다(PRD 6.2항).

인수: `$ARGUMENTS`

## 절대 지킬 것

- **사용자가 승인하기 전에는 어떤 파일도 고치지 않는다.** 먼저 만든 문항을 보여 주고 멈춘다.
- 승인 뒤에도 고치는 파일은 `questions.js` 하나뿐이다. 다른 파일(`CLAUDE.md`, `PRD.md`, `IMPL-PLAN.md`, `script.js`, `index.html`)은 건드리지 않는다.
- 4개 카테고리에 **모두 n개씩** 들어갈 때만 넣는다. 일부 카테고리만 넣거나, 카테고리마다 개수가 다르게 넣지 않는다.
- 출처는 **이번에 실제로 열어 내용을 확인한 페이지만** 적는다. 검색 결과 요약이나 기억만 보고 적지 않는다. 열지 못한 페이지는 출처로 쓰지 않는다.
- 커밋, push는 하지 않는다.

## 0. 인수 확인

- `$ARGUMENTS`가 1 이상의 정수가 아니면(비었거나, 0, 음수, 소수, 글자) 아무것도 하지 말고 아래처럼 알린 뒤 멈춘다.
  - `사용법: /quiz-add <n>  (예: /quiz-add 2 → 카테고리마다 2개, 모두 8개)`
- n이 5보다 크면 만들 문항 수(`4 × n`개)와 출처 확인에 시간이 걸린다는 점을 알리고, 계속할지 사용자에게 먼저 묻는다.

## 1. 읽을 것

1. `CLAUDE.md`의 「## 문항 작성 규칙」 규칙 1~10. 문항은 이 규칙을 모두 지켜야 한다. 아래 설명보다 `CLAUDE.md`의 현재 내용이 우선이다.
2. `PRD.md`의 「6.1 데이터 형식」, 「6.2 문항 규칙」, 「6.3 문항 작성과 확인」.
3. `questions.js` 전체. 문항 형식과 이미 있는 문항(겹치지 않게 하기 위해)을 확인한다.
   - 지금 카테고리마다 문항 수가 같은지 센다. 다르면 문항을 만들지 말고 그 사실과 카테고리별 개수를 알린 뒤 멈춘다.

## 2. 문항 만들기

카테고리마다 n개씩, 모두 `4 × n`개를 만든다.

### 형식 (PRD 6.1항)

```js
  {
    id: "kh-11",
    category: "한국사",
    question: "...?",
    choices: ["...", "...", "...", "..."],
    answer: "...",
    explanation: "...",
    source: "자료명, URL, YYYY-MM-DD",
  },
```

- `id`: 카테고리 약자 + `-` + 두 자리 번호. 약자는 `kh` 한국사, `wg` 세계지리, `sc` 과학, `ac` 예술과 문화. 번호는 그 카테고리의 가장 큰 번호 다음부터 이어 쓴다(예: `kh-10`이 마지막이면 `kh-11`부터).
- `answer`: 정답 보기의 **내용**(문자열). `choices`에 정확히 1번 나와야 한다.
- `explanation`: 한 줄 해설. 기존 문항처럼 "~함", "~임"으로 끝낸다.
- `source`: `"자료명, URL, 확인한 날짜"` 한 줄. 날짜는 오늘 날짜(`YYYY-MM-DD`). 자료명은 기존 문항처럼 `기관/사전 이름 「항목」` 또는 `Britannica "제목"` 형태로 쓴다.
- 기존 문항과 주제가 겹치는 문항은 만들지 않는다. 겹침은 아래 「겹침 확인」으로 판정한다.
- 난이도와 주제는 기존 문항과 비슷하게 맞춘다(대학 1학년 상식 수준).

### 규칙 확인 (CLAUDE.md 규칙 1~10)

문항마다 아래를 확인하고, 하나라도 어기면 고치거나 다른 문항으로 바꾼다.

1. 정답은 하나뿐이고, 다른 보기가 기준(시점, 단위, 범위)에 따라 정답이 될 여지가 없다.
2. 최상급 표현("가장, 최대, 최초" 등)을 쓰면 기준과 시점을 문제 문장에 적는다.
3. 보기 4개가 서로 다르다.
4. 사실은 **출처 2곳 이상**에서 확인한다. 출처끼리 값이 다르면 그 값은 문제와 해설에 쓰지 않는다.
5. 출처 문장을 옮긴 뒤 문제 문장이 문법에 맞고 자연스러운지 다시 읽는다.
6. 정답과 해설이 서로 맞는다.
7. 오답 3개도 정답과 같은 유형이고, 모르는 사람에게는 답이 될 법하다.
8. 보기 4개의 길이와 형식(단위, 띄어쓰기, 표기)이 비슷하다.
9. 문제 문장이 부정문("~이 아닌 것은?")이 아니다.
10. "모두 맞음", "위의 어느 것도 아님" 같은 보기가 없다.

### 겹침 확인 (기존 문항과 주제가 겹치지 않게)

- 새 문항마다 `question`과 `answer`에 나오는 **인물, 사건, 작품, 지명**을 뽑는다.
- `questions.js`의 기존 문항 전체(모든 카테고리)의 `question`과 `answer`에서 같은 인물, 사건, 작품, 지명이 나오는 문항을 찾아 그 `id`를 적어 둔다. 없으면 "없음"이다.
  - 표기가 달라도 같은 대상이면 같은 것으로 본다(예: "이순신"과 "충무공", "에베레스트산"과 "초모룽마").
  - 이번에 새로 만든 문항끼리도 같은 방법으로 비교한다.
- 겹치는 `id`가 하나라도 있으면 그 문항은 **보여 주기 전에** 다른 인물, 사건, 작품, 지명을 다루는 문항으로 바꿔 다시 만든다. 다시 만든 문항도 규칙 확인, 겹침 확인, 3단계 출처 확인을 처음부터 다시 거친다.
- 바꾼 초안은 4단계 미리 보기 아래의 "겹쳐서 바꾼 초안"에 적는다.

## 3. 출처 확인 (실제로 열기)

- 문항마다 출처 페이지를 **2곳 이상 실제로 연다.** 공공기관, 백과사전(예: 우리역사넷, 한국민족문화대백과사전, 브리태니커, NASA, 박물관·미술관)을 우선한다.
  - WebFetch로 연다. WebFetch가 막히면(403 등) 브라우저 패인(`mcp__Claude_Browser__*`)으로 열어 본문을 읽는다.
  - 두 방법 모두로 열지 못하면 그 출처는 쓰지 않고 다른 출처를 찾는다. 출처 2곳을 확인하지 못한 문항은 다른 문항으로 바꾼다.
- 열어 본 페이지에서 문제, 정답, 해설의 사실과 오답 3개가 틀렸다는 근거를 확인한다.
- `source`에는 확인한 출처 중 가장 공신력 있는 1곳을 적는다(PRD 6.1 형식은 한 줄). 나머지 출처는 미리 보기에만 적는다.

## 4. 미리 보기 (여기서 멈춤)

만든 문항을 카테고리별로 보여 준다. **파일은 아직 고치지 않는다.**

카테고리마다 아래 표를 하나씩 보여 준다.

| id | 문제 | 보기 (정답에 ✓) | 해설 | 확인한 출처 | 기존 문항과 겹침 |
|---|---|---|---|---|---|
| kh-11 | ... | ✓ 정답 / 오답1 / 오답2 / 오답3 | ... | ① 자료명 URL (source에 적음) ② 자료명 URL | 없음 |

- **기존 문항과 겹침**: 2단계 「겹침 확인」에서 찾은, 인물·사건·작품·지명이 같은 기존 문항의 `id`를 쉼표로 적는다. 없으면 "없음"이라고 적는다.
  - 겹치는 문항은 보여 주기 전에 바꿔야 하므로, 이 칸은 모든 문항이 "없음"이어야 한다. "없음"이 아닌 문항이 남아 있으면 미리 보기를 멈추고 그 문항부터 다시 만든다.

표 아래에 다음을 적는다.

- `카테고리마다 n개, 모두 4×n개를 만들었습니다. 넣은 뒤 카테고리마다 m개가 됩니다.`
- 겹쳐서 바꾼 초안: `초안 주제 → 겹친 기존 id → 바꾼 새 문항 id` 형식으로 한 줄씩 적는다. 없으면 "없음".
- 규칙 1~10 확인 결과. 애매해서 사용자가 봐 주면 좋을 문항이 있으면 id와 이유를 적는다.
- 마지막 줄에 묻는다: `이대로 questions.js에 넣을까요? (전부 승인 / 고칠 문항 id와 이유 / 취소)`

그리고 **사용자의 답을 기다린다.**

## 5. 사용자의 답에 따라

- **전부 승인**: 6단계로 간다.
- **일부를 고치거나 바꿔 달라고 함**: 그 문항만 다시 만들고(2단계 겹침 확인과 3단계 출처 확인 포함), 바뀐 문항만 다시 보여 준 뒤 다시 승인을 받는다. 카테고리마다 n개라는 개수는 그대로 지킨다.
- **일부만 빼 달라고 함**: 그대로 빼면 개수가 달라지므로, 빠진 자리에 같은 카테고리의 새 문항을 만들어(2단계 겹침 확인과 3단계 출처 확인 포함) 다시 보여 준다. 개수를 줄이고 싶다면 다른 카테고리에서도 같은 수를 빼야 한다는 점을 알리고 어느 쪽으로 할지 묻는다.
- **취소**: 아무것도 고치지 않고 끝낸다.

## 6. questions.js에 넣기 (승인 뒤에만)

1. 각 카테고리의 새 문항을 그 카테고리 묶음의 **맨 끝**에 넣는다. 묶음은 `// 한국사`, `// 세계지리`, `// 과학`, `// 예술과 문화` 주석으로 나뉘며, 다음 카테고리 주석 바로 앞의 빈 줄 위(마지막 카테고리는 `];` 위)가 끝이다.
2. 들여쓰기(2칸), 따옴표, 줄 끝 쉼표를 기존 문항과 똑같이 맞춘다. 문자열 안의 큰따옴표는 `\"`로 쓴다.
3. 넣은 뒤 아래 두 가지를 실행해 확인한다.
   - IMPL-PLAN.md Task 1 Step 5의 Node 문항 검사. 카테고리마다 문항 수가 같은지, 보기 4개가 서로 다른지, 정답이 보기에 정확히 1번 나오는지 본다. 기대 출력은 `문항 검사 통과: <전체 문항 수>문항`.
   - `node script.js`. 끝 줄이 `점검 통과: N개`여야 한다.
   - 실패하면 고쳐서 다시 실행하고, 그래도 안 되면 무엇이 실패했는지 그대로 보고한다.
4. 보고: 넣은 문항 id 목록, 카테고리별 문항 수(넣기 전 → 넣은 뒤), 두 검사 결과. 커밋은 하지 않고, 사용자가 브라우저에서 새 문항을 확인해 보라고 안내한다.
